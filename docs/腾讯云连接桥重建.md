# 腾讯云连接桥重建

连接桥分两层：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 心潮后端 `BRIDGE_*` | `xinchao-dynamic-mind` 的 `.env` | 开启 `/bridge/v1/*` 队列、签发机器 token、决定是否入队 `self_signal` |
| Runtime Bridge `XINCHAO_BRIDGE_*` | 腾讯云常驻进程的 env | 连接队列、读取投递、交给 process 或 webhook adapter、回传 ACK |

## 1. 开启心潮后端桥队列

在心潮后端 `.env` 中设置：

```bash
BRIDGE_ENABLED=true
BRIDGE_MACHINE_TOKEN=<openssl rand -hex 32 的输出，至少 32 字符>
BRIDGE_STATE_PATH=/app/state/bridge-queue.json
BRIDGE_SELF_SIGNALS=true
```

重启心潮服务后检查：

```bash
curl -s -H "Authorization: Bearer $BRIDGE_MACHINE_TOKEN" \
  http://127.0.0.1:18110/bridge/v1/health
```

期望返回：

```json
{"protocol":"xinchao-bridge-server/1","status":"ok"}
```

## 2. 安装 Runtime Bridge 常驻进程

在腾讯云服务器上的本仓库目录执行：

```bash
sudo bash scripts/install-runtime-bridge.sh
```

第一次运行会创建 `/etc/xinchao-runtime-bridge.env` 并停下。编辑它：

```bash
sudo nano /etc/xinchao-runtime-bridge.env
```

本机同服务器部署时，基础配置通常是：

```bash
XINCHAO_BRIDGE_BASE_URL=http://127.0.0.1:18110
XINCHAO_BRIDGE_MACHINE_TOKEN=<同一个 BRIDGE_MACHINE_TOKEN>
XINCHAO_BRIDGE_ACCEPT_SELF_SIGNALS=true
XINCHAO_BRIDGE_LOG_LEVEL=info
```

再选择一种投递目标。

### webhook 模式

给自建前端或自己的后端：

```bash
XINCHAO_BRIDGE_INJECTOR_MODE=webhook
XINCHAO_BRIDGE_WEBHOOK_URL=https://your-runtime.example.com/xinchao/wake
XINCHAO_BRIDGE_WEBHOOK_TOKEN=<另一串独立 token>
```

接收端必须在消息真正进入目标会话后返回：

```json
{"accepted":true,"deliveryId":"原 deliveryId"}
```

### process 模式

给同机 CLI/Agent adapter：

```bash
XINCHAO_BRIDGE_INJECTOR_MODE=process
XINCHAO_BRIDGE_INJECTOR_EXECUTABLE=node
XINCHAO_BRIDGE_INJECTOR_ARGS_JSON=["/absolute/path/to/adapter.mjs"]
```

adapter 从 stdin 读取一行 JSON，成功投递到目标会话后退出码为 `0`。

## 3. 启动与检查

env 填好后再次执行：

```bash
sudo bash scripts/install-runtime-bridge.sh
```

查看服务：

```bash
systemctl status xinchao-runtime-bridge --no-pager
journalctl -u xinchao-runtime-bridge -n 80 --no-pager
```

只检查桥配置：

```bash
cd /opt/xinchao-runtime-bridge
set -a
source /etc/xinchao-runtime-bridge.env
set +a
node src/cli.js check
```

## 4. 常见判断

- `/bridge/v1/health` 返回 401：`BRIDGE_MACHINE_TOKEN` 与 `XINCHAO_BRIDGE_MACHINE_TOKEN` 不一致。
- `check` 失败且连不上：`XINCHAO_BRIDGE_BASE_URL` 地址不对，或心潮后端没开启 `BRIDGE_ENABLED=true`。
- 服务显示运行但没有投递：确认心潮后端真的产生了队列项，且接收端 webhook/process adapter 严格 ACK。
- 不想接心潮自身信号：后端 `BRIDGE_SELF_SIGNALS=false` 或桥进程 `XINCHAO_BRIDGE_ACCEPT_SELF_SIGNALS=false` 任意一边关闭即可。
